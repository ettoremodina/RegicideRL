King tier · Research horizon

Make strong decisions cheaper to understand.

The current project closes around ISMCTS. The most valuable next work is optional research: learn a stronger policy, compress search into a transparent agent, or extend information-set planning to cooperative multiplayer.

Two primary directions

Long-horizon research

Complete the AlphaZero path

The repository contains early components for self-play, a policy/value network, replay buffers, checkpoints, and MCTS. A future project could finish and validate the complete loop: reproducible self-play, masked policy targets, stable training, and evaluation against ISMCTS at explicit compute budgets.

This is not a completed model and is not required for the current release.

Practical & interpretable

Distill search into a lightweight agent

Record ISMCTS decisions together with human-readable state features, then train a small decision tree, rule list, or sparse model to imitate them. The target is millisecond decisions with explanations such as “preserve exact defense” or “cancel King immunity,” not merely a smaller opaque network.

Evaluation should measure fidelity, win rate, castle progress, latency, and explanation stability.

Other useful extensions

Multiplayer ISMCTS

Represent each observer's information set and cooperative communication rules for two to four players, then test whether a shared objective is enough to coordinate hidden hands.

Anytime search

Profile cloning and rollouts, retain trees safely across observations, and expose time budgets so the same agent can answer quickly in the UI or search deeply offline.

Decision explanations

Turn root visit counts, alternatives, and heuristic features into concise hints: recommended move, expected progress, uncertainty, and the strongest rejected action.

Lessons from PPO

PPO was a useful engineering exercise because it forced a stable action mask and numeric observation path. It was not a successful project outcome: training was too long, the available results were poor, and the final comparison had no valid promoted checkpoint. Repeating the same training at larger scale is therefore not a priority.

A future learned agent should earn its complexity by beating clear baselines under a fixed compute and data budget. Until then, the rules-based and search agents remain the trustworthy reference.

A clean research protocol

  1. Freeze the question. Define the player count, information available, compute budget, and primary outcome before training.
  2. Keep a non-neural control. Compare against Heuristic, PIMC, and ISMCTS using paired seeds.
  3. Publish failed runs. Preserve configs and reasons, but never promote incomplete runs into measured charts.
  4. Report utility, cost, and clarity. Win rate alone cannot distinguish a usable agent from an expensive black box.
