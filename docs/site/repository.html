King tier · Codebase guide

Find the layer you need.

The repository separates game truth, decision makers, interfaces, experiment workflows, and durable run output. Start from an entry point, then follow its imports inward toward the rules engine.

Top-level map

  • game/ — rules engine, action encoding, legal masks
  • agents/ — Random, Heuristic, PIMC, ISMCTS, PPO, AlphaZero adapters
  • solvers/ — Gymnasium environment, training, analysis, AlphaZero prototype
  • ui/ — Pygame desktop application
  • control_panel/ — local browser launcher and artifact explorer
  • scripts/
    • experimental_report/ — runner, statistics, plots, report pipeline
    • build_report_site.py — publish this site's charts and source data
  • ml_logger/ — logging, metrics, run manifests, terminal and HTML views
  • integrations/ — game recording bridge
  • tests/ — rules, environment, logging, docs, and workflow checks
  • docs/
    • api/ — generated API reference
    • site/ — this field guide and its publication data
    • planning/ — historical plans and closure notes
  • artifacts/runs/ — reproducible outputs grouped by date and run ID

Core directories

Domain

game/

regicide.py owns cards, enemies, setup, combat, suit powers, defense, and victory. action_handler.py maps hands to legal global actions.

Decision

agents/

All agents implement the same selection interface. Search agents clone and determinize RegicideEnv; learned agents adapt external policy objects.

Environment

solvers/

env.py exposes the 543-action Gymnasium contract. Wrappers, training entry points, evaluation, and experimental AlphaZero components live nearby.

Human play

ui/

The Pygame application renders the current enemy, hand, selections, feedback, and AI play while delegating all rule decisions to the engine.

Operations

control_panel/

A browser UI bound to 127.0.0.1 validates configuration, launches registered commands, follows jobs, and exposes permitted artifacts.

Evidence

artifacts/

Each run preserves a manifest, effective config, logs, metrics, game datasets, checkpoints, and analysis without mixing generated output into source modules.

Entry points

Play and operate

python -m ui
python -m control_panel
python -m scripts.log_game

Evaluate and verify

python benchmark.py
python -m scripts.experimental_report.orchestrator
python scripts/build_report_site.py
pytest

Configuration and output

config.yaml is the primary behavior and experiment configuration. logger_config.yaml controls the artifact root, console presentation, recording, and per-run-type policies. config_test.yaml provides smaller test-oriented values.

Run output is immutable evidence, not application configuration. A typical report run stores:

artifacts/runs/YYYY-MM-DD/experimental-report-<id>/
├── manifest.json
├── experimental_report_config.yaml
├── datasets/games.csv
├── metrics/metrics.jsonl
├── logs/run.log
└── analysis/

Safe path through the code: change official behavior in game/ and add rule tests first; change representation in ActionHandler and RegicideEnv together; keep agents from reimplementing rules.
